# NEON COIL — 게임 기획서

> 버전 0.1 · 2026-08-15 · 성장 경쟁 액션 (slither.io 계열)
> 자매작 [NEON PURGE](https://github.com/sehoi/neon-purge)와 같은 세계관·아트·기술 스택을 쓴다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| **타이틀** | NEON COIL (네온 코일) |
| **장르** | 성장 경쟁 액션 / 아레나 서바이벌 |
| **플랫폼** | 웹 브라우저 (데스크톱 + 모바일 터치) |
| **플레이 인원** | 1인 (NPC 19기와 경쟁, **서버 없음**) |
| **1회 플레이 시간** | 2~6분 (죽을 때까지) |
| **기술 스택** | HTML5 Canvas 2D + 순수 ES 모듈 (빌드 도구·라이브러리·에셋 **0개**) |

### 한 줄 컨셉
> 메인프레임의 대역폭을 놓고 경쟁하는 데이터 코일이 되어, 다른 프로세스를 들이받아 터뜨리고 그 잔해를 삼켜 가장 길어진다.

### 왜 이 설계인가 (제작 속도 관점)

**NEON PURGE에서 그대로 가져오는 것** — 이게 이 프로젝트의 출발점이다.

| 재사용 | 무엇을 아끼는가 |
|---|---|
| `core/` 전체 (input · audio · pool · grid · rng · vec · save) | 터치 조이스틱, 절차 사운드, 공간 해시, 저장 로직을 다시 안 짠다 |
| 네온 렌더 기법 (이중 스트로크, 적응형 품질) | `shadowBlur`로 프레임을 날려먹는 시행착오를 건너뛴다 |
| 동적 논리 해상도 + safe-area + 전체화면 | 모바일 화면 대응이 이미 풀려 있다 |
| UI 위젯 · 화면 전환 · 탭 큐 입력 | 버튼이 안 눌리는 부류의 버그를 다시 겪지 않는다 |
| 성능 원칙 (프레임당 할당 0, 콜백 클로저 금지) | 처음부터 지키고 시작한다 |

**새로 설계해야 하는 것은 넷뿐이다.** 몸통 표현, 뱀-뱀 충돌, NPC AI, 순위 UI.

**서버가 없다** — 진짜 멀티플레이는 서버·동기화·보간·치팅 대응이 전부 따라온다. NPC로 대체하면 그 비용이 통째로 사라지고, 혼자서도 언제든 붐비는 아레나를 만들 수 있다.

## 2. 코어 루프

```
 방향을 조종해 데이터 조각을 삼킨다
        ↓
 길이가 늘고 몸이 굵어진다
        ↓
 다른 코일의 진로를 몸으로 막는다
        ↓
 상대가 내 몸에 박고 터진다 → 잔해를 대량 흡수
        ↓
 순위가 오른다 ⟷ 커질수록 회피가 어려워진다
        ↓
 내 머리가 남의 몸에 닿는 순간 끝
```

**설계 의도**: 커질수록 강해지는 동시에 **커질수록 죽기 쉬워진다**. 이 긴장이 없으면 그냥 먹기 노동이 된다. 몸이 길어지면 회전 반경이 실질적으로 커지고, 남의 몸을 피할 공간이 줄어든다.

## 3. 조작

| 입력 | 동작 |
|---|---|
| `WASD` / 방향키 (기본) | 누른 방향이 곧 머리가 향할 방향. 두 개를 같이 누르면 대각선 |
| `Shift` / `Space` | 부스트 |
| 마우스 이동 (선택) | 머리가 포인터 방향으로 향한다 (조준이 아니라 **방향 지시**) |
| 마우스 좌클릭 (마우스 조종일 때) | 부스트 |
| 터치 드래그 | 누른 지점 기준 조이스틱 — 미는 방향으로 향한다 |
| 우하단 원 (터치) | 부스트 |
| `Esc` / `P` / 상단 `▮▮` | 일시정지 |

**조작 규칙 네 가지**

1. **머리는 목표 각도로 즉시 꺾이지 않는다.** 초당 최대 회전 속도(`turnRate`)가 있고, 몸이 길수록 조금씩 둔해진다. 이게 없으면 조작 난이도가 사라져 회피가 무의미해진다.
2. **키보드와 마우스는 섞지 않는다.** 처음에는 "키가 눌려 있으면 키, 아니면 마우스"였는데, 마우스 조종은 포인터가 화면 어디에 있든 **항상** 방향을 지시한다. 그래서 키를 떼는 순간 조종권이 포인터로 넘어가 코일이 제멋대로 꺾였고, 키보드로 하려 해도 할 수가 없었다. 설정으로 하나만 쓴다(기본 키보드).
3. **터치 조이스틱은 절대 방향이 아니라 상대 방향이다.** 누른 자리가 원점이고, 민 방향이 진행 방향이다. NEON PURGE와 동일한 규칙이라 손이 기억한다.
4. **상태가 바뀌는 순간 닿아 있던 손가락은 무시한다.** (NEON PURGE에서 레벨업 카드가 제멋대로 눌리던 문제와 같은 부류)

**8방향으로 충분한가.** 키보드는 45° 단위로만 목표를 줄 수 있어 마우스보다 거칠다. 다만 회전 속도 제한이 이미 있어서 목표가 45° 떨어져 있어도 머리는 부드러운 호를 그리며 돈다(실측: 45° 도는 데 0.22초). 선회도 8방향을 순서대로 눌러 만든다 — 실측으로 1.87초에 315°를 돌아 출발점 16px 안으로 돌아왔다. 포위 자체가 이 게임의 주력 전술은 아니라(NPC 회피 가중치 6.0) 앞을 가로막는 쪽이 주력이고, 그건 8방향으로 충분하다.

## 4. 코일 (플레이어 · NPC 공통)

| 스탯 | 값 | 비고 |
|---|---|---|
| 기본 속도 | 190 px/s | |
| 부스트 속도 | 340 px/s | 1.8배 |
| 회전 속도 | 3.4 rad/s → 2.2 rad/s | 길이 20 → 400 구간에서 선형 감소 |
| 시작 길이 | 24 세그먼트 | |
| 몸 반지름 | 7 px → 20 px | 길이에 따라 증가, 상한 20 |
| 세그먼트 간격 | 반지름 × 0.55 | 몸이 끊겨 보이지 않을 만큼 |
| 머리 히트박스 | 반지름 × 0.8 | 억울한 죽음 방지 — 머리를 실제보다 작게 |

### 부스트
- 속도 1.8배
- **초당 길이 6 소모**, 소모한 만큼 꼬리 끝에서 데이터 조각을 흘린다 (남이 주울 수 있다)
- 길이 20 이하에서는 부스트 불가
- 추격·탈출·차단 모두에 쓰이는 유일한 자원

### 사망
- **내 머리**가 다른 코일의 **몸통**에 닿으면 사망
- 머리끼리 정면충돌하면 **짧은 쪽이 사망** (같으면 둘 다)
- 자기 몸통과는 충돌하지 않는다 (slither.io 방식 — 자기 몸에 갇히는 답답함이 재미를 깎는다)
- 아레나 경계 밖으로 나가면 사망
- 사망 시 몸 전체가 데이터 조각으로 흩어진다 (길이에 비례한 양)

## 5. 아레나

- **원형, 반지름 2,600px**. 경계는 붉은 네온 링으로 그린다.
- 경계에 접근하면 화면 가장자리에 경고 비네트.
- 배경은 NEON PURGE와 같은 격자 (터치에서는 성기게).

**왜 유한한가**: 무한 평면이면 도망이 항상 정답이 되어 경쟁이 성립하지 않는다. 경계는 압박 장치다.

## 6. 데이터 조각 (먹이)

| 종류 | 크기 | 길이 증가 | 출처 |
|---|---|---|---|
| **비트** | r 4 | +1 | 상시 스폰 |
| **블록** | r 7 | +4 | 상시 스폰 (20%) |
| **잔해** | r 9 | +6 | 코일 사망 시 |
| **누출** | r 3 | +1 | 부스트 중 꼬리에서 배출 |

- 아레나 전체에 **상시 1,400개** 유지. 부족하면 화면 밖 랜덤 위치에 보충한다.
- 머리 반경 + 흡인 범위(40px) 안에 들어오면 빨려온다.

## 7. NPC (19기)

서버 없이 붐비는 느낌을 만드는 핵심. **성격 3종**을 섞는다.

| 성격 | 비율 | 행동 |
|---|---|---|
| **수집형** | 50% | 가까운 먹이 무리로 향한다. 위험하면 즉시 회피. 부스트는 도망칠 때만. |
| **사냥형** | 30% | 자기보다 짧은 코일의 **진행 방향 앞을 가로막는다**. 차단 각도에 들어가면 부스트. |
| **신중형** | 20% | 큰 코일 반경 400px 안에 절대 안 들어간다. 경계 근처 먹이를 독식한다. |

### AI 판단 (매 프레임, 벡터 합산)
```
목표방향 = 먹이유인(w1) + 위험회피(w2) + 경계회피(w3) + 차단벡터(w4, 사냥형만)
```
- **위험회피**가 항상 최우선 — 전방 부채꼴(±60°, 거리 220px)에 남의 몸통이 있으면 회피 벡터가 지배한다.
- 회피 실패 시 부스트로 빠져나간다.
- **NPC도 죽는다.** 죽으면 3~6초 뒤 경계 근처에서 새로 들어온다(리스폰). 아레나 인구가 유지되어야 한다.

**중요**: NPC가 완벽하면 재미없고, 멍청하면 경쟁이 안 된다. 목표는 **"가끔 나를 죽이고 자기들끼리도 죽는"** 수준이다.

## 8. 순위 · UI

- **리더보드**: 우상단, 상위 5기 + 내 순위. 길이 기준. 0.5초마다 갱신(매 프레임 정렬은 낭비).
- **미니맵**: 우하단 원형. 내 위치, 상위 3기, 경계.
- **길이 표시**: 좌상단 크게.
- **부스트 게이지**: 터치는 버튼 링, 데스크톱은 길이 숫자 옆 작은 바.

터치에서는 NEON PURGE와 같은 규칙 — **중요한 정보는 위쪽**, 손에 가리는 하단은 조작 전용.

## 10. 아트

NEON PURGE의 팔레트와 렌더 기법을 그대로 쓴다.

| 역할 | 색 |
|---|---|
| 배경 / 격자 | `#070711` / `#151a35` |
| 플레이어 코일 | `#00f0ff` (시안) |
| NPC 코일 | 6색 순환 — 마젠타·라임·금·보라·오렌지·민트 |
| 데이터 조각 | 라임 → 금 → 백색 (크기별) |
| 경계 링 | `#ff3b3b` |

- 코일 몸통은 **폴리라인 한 번의 stroke**로 그린다 (원 200개가 아니라). 이게 성능의 핵심이다.
- 네온은 이중 스트로크 (굵은 반투명 + 얇은 밝은 코어). `shadowBlur` 금지.
- 머리에는 눈 두 개 — 방향이 읽혀야 한다.
- 사망 연출: 몸 전체가 조각으로 터지며 화면 흔들림.
