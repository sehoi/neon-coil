# NEON TRIAD

브라우저에서 바로 돌아가는 **3D 물리 3매치**. 상자에 타일을 쏟아 쌓고, 무늬가 보이는 타일을 집어 같은 것 셋을 모은다.
[NEON COIL](../) 과 같은 규칙으로 만들었다 — 빌드 도구도, 외부 라이브러리도, 에셋 파일도 없다.
**강체 물리 엔진도 직접 썼다.** 타일과 무늬는 Canvas 벡터, 사운드는 WebAudio 절차 생성.

### ▶ [지금 플레이하기](https://sehoi.github.io/neon-coil/triad/)

## 로컬에서 실행

저장소 루트에서:

```bash
node serve.mjs
```

그 다음 http://localhost:5173/triad/ 를 연다.
(ES 모듈은 `file://` 에서 CORS 로 막히므로 `index.html` 을 더블클릭하면 동작하지 않는다)

## 규칙

- 타일은 층으로 놓이지 않는다. **상자에 쏟아져 물리로 쌓인 대로** 놓인다 — 옆으로 넘어지고, 엎어지고, 남의 위에 걸친다.
- **무늬가 보이면 집을 수 있다.** 더미 꼭대기든 옆구리든 상관없다. 앞면이 조금이라도 카메라를 향하면 그 타일은 내 것이다.
- **엎어졌거나 모로 선 타일은 못 집는다.** 눌러도 흔들리기만 한다 → `뒤집기` 도구를 쓴다.
- 집은 타일은 **트레이 7칸**에 쌓이고, 같은 무늬 3장이 모이면 사라진다.
- 한 장을 빼면 그 위에 얹혀 있던 것들이 **실제로 무너진다.** 무너지면서 보이는 무늬가 바뀐다.
- 판을 다 비우면 다음 레벨. **트레이가 다 차면 그 판은 끝난다.**

### 도구

레벨마다 다시 채워진다.

| 도구 | 키 | 효과 |
|---|---|---|
| **되돌리기** | `Z` | 마지막에 집은 한 장을 더미 위로 되돌린다 (레벨당 3회) |
| **빼내기** | `X` | 트레이에서 3장을 더미 위로 쏟는다 (레벨당 1회) |
| **뒤집기** | `V` | 위가 트인 엎어진 타일을 뒤집는다 (레벨 2부터, 2회) |
| **섞기** | `C` | 남은 타일을 통째로 다시 쏟는다 (레벨 3부터, 1회) |

트레이가 차서 진 뒤에도 **빼내기가 남아 있으면 그 자리에서 이어할 수 있다.**

## 물리 엔진

라이브러리를 쓰지 않았으므로 박스 강체 시뮬레이션을 직접 썼다 (`src/game/physics.js`, 약 500줄).
**XPBD**(확장 위치 기반 동역학) — 속도가 아니라 위치를 직접 고치고 서브스텝을 잘게 쪼갠다.
납작한 박스가 여러 겹으로 쌓이는 상황에서 속도 기반 솔버보다 훨씬 조용히 선다.

- 접촉은 **SAT**(15축) 으로 찾고, 면끼리 닿으면 기준면에 상대 면을 **잘라 붙여 최대 4점**을, 모서리끼리 엇갈리면 두 선분의 최근접점 하나를 만든다.
- 서브스텝 6, 접촉은 **서브스텝마다 다시** 만든다.
- 마찰은 접점이 옆으로 미끄러진 양을 되돌리는 방식(정지 마찰), 계수 0.72.

세 가지가 특히 중요했다. 셋 다 실측으로 찾았다:

| 증상 | 원인과 대응 |
|---|---|
| 더미가 폭발한다 (타일이 y=8000 까지 날아감) | 위치 보정이 그대로 속도가 된다 (`v = Δp/h`, h=1/360초). 반발이 없는 물체이므로 **접촉면에서 멀어지는 속도를 0 으로 깎는 속도 패스**를 서브스텝마다 4회 돌린다 |
| 더미가 영영 부글거린다 (maxV 7~12) | 접촉 앵커를 한 스텝 내내 고정하면 그게 핀처럼 작용해 에너지를 계속 밀어 넣는다. **서브스텝마다 접촉을 다시 만들자 maxV 0.7 로** 떨어졌다 |
| 아무도 잠들지 않는다 | 깨울 때 `sleepT` 을 지우면, 이웃 하나가 뒤척이는 동안 온 더미가 못 잔다. **깨어날 때 타이머를 보존**하고, 접촉 생성 단계에서 미리 깨워 한쪽만 정적으로 취급되는 비대칭을 없앤다 |

검증 (`node triad/tools/physlab.mjs 12 2`) — 게임과 똑같은 방식으로 쏟는다:

| 레벨 | 타일 | 정착 | 스텝 | 최대 관통 | 상자 밖 | 앞면 비율 |
|---|---|---|---|---|---|---|
| 1 | 24 | 4.5초 | 1.3~1.8 ms | 0.04 | 0 | 79~88% |
| 5 | 48 | 5.1초 | 2.3~2.4 ms | 0.004 | 0 | 85~92% |
| 9 | 72 | 5.6초 | 3.8~4.2 ms | 0.02 | 0 | 81~86% |
| 11 | 84 | 5.9초 | 4.4~4.8 ms | 0.006 | 0 | 85~86% |

관통은 타일 두께(0.52) 대비다. 정착 시간에는 쏟는 시간(1.3~2초)이 포함돼 있고,
그 뒤로도 눈에 안 보이는 미동이 남으면 4초 뒤 그냥 세운다 — 프레임을 계속 먹기 때문이다.

## "보이면 집힌다"를 정확히 만들기

클릭 판정은 **그림이 아니라 레이-상자 교차**로 한다 (`raycast`). 화면의 한 점에서 광선을 쏘아
가장 먼저 맞는 타일을 고르고, **맞은 면이 앞면(로컬 +z)일 때만** 집힌다. 그래서

- 화가 알고리즘(면 단위 깊이 정렬)이 한두 번 틀려도 "보이는데 안 눌린다"가 생기지 않는다.
- 힌트·검증도 같은 판정을 쓴다: `visibleFront` 는 타일마다 앞면의 표본 다섯 점을 카메라로 투영해
  그 지점에서 광선을 되쏜다. 브라우저와 node 가 완전히 같은 답을 낸다.

### 굳은 판 구제

남은 타일이 전부 엎어지면 아무것도 집을 수 없고, 트레이는 차지 않으니 지지도 않는다 — 판이 굳는다.
그래서 0.5초마다 확인한다:

1. **싼 검사** — 타일마다 카메라에서 광선 하나. 앞면이 보이는 게 하나라도 있으면 통과.
2. 걸리면 **비싼 검사**(`visibleFront`) 로 한 번 더 확인한다. 구석만 삐죽 보이는 타일을 놓치지 않으려고.
3. 그래도 없으면 도구를 쓰지 않고 **엎어진 타일을 뒤집어 준다.** 플레이어 잘못이 아니라 물리가 만든 막다른 길이다.
4. 뒤집을 것조차 없으면(처마 밑에 깔린 채 굳은 경우) **통째로 다시 쏟는다.**

## 난이도

봇이 실제로 판을 푸는 시뮬레이션 (`node triad/tools/simulate.mjs 12 5`).
게임 로직·물리·카메라가 모두 DOM 을 모르므로 node 에서 그대로 돌아간다.

| 레벨 | 타일 | 무늬 | 봇 클리어율 |
|---|---|---|---|
| 1 | 24 | 4 | 100% |
| 2 | 30 | 4 | 80% |
| 3~6 | 36~54 | 5~6 | 100% |
| 7~8 | 60~66 | 6 | 80% |
| 9~10 | 72~78 | 7 | 20~80% |

레벨 9 에서 한 번 크게 꺾이는데, 판마다 편차가 커서(같은 레벨에서 20% 와 80% 가 나온다)
아직 곡선이라고 부르기는 이르다. 사람 손으로 더 두어 봐야 한다.

봇은 보이는 타일을 완전히 알고 손도 안 떨린다. 대신 앞을 못 본다 —
"지금 보이는 것" 중에서만 고르고, 몰릴 때만 도구를 쓴다. 사람은 여기서 더 잘하기도, 더 못하기도 한다.

## 조작

| 입력 | 동작 |
|---|---|
| 클릭 / 탭 | 무늬가 보이는 타일 집기 · 버튼 |
| `Z` `X` `V` `C` | 되돌리기 · 빼내기 · 뒤집기 · 섞기 |
| `Esc` / `P` | 일시정지 |
| `M` / `G` | 음소거 / 글로우 전환 |

세로 화면 720×1280 논리 해상도를 레터박스로 맞춘다. 모바일은 세로로 잡고 하면 된다.

## 성능

3D 더미는 픽셀을 많이 칠한다. 두 가지를 조심했다:

- **DPR 상한 1.75.** 고DPI 기기에서 원본 배율로 그리면 채우기만으로 프레임이 무너진다.
- **배경 캐시.** 전면 그라디언트를 프레임마다 다시 칠하면 그것만으로 15ms 가 날아간다. 한 번 그려 두고 복사한다.

물리는 더미가 잠들면 계산 자체를 멈춘다. 타일을 하나 빼면 그 주변만 깨어난다.

## 구조

```
index.html · style.css
src/
  main.js        루프 + 상태 머신 (title · play · pause · clear · over)
  config.js      논리 해상도 · 화면 영역 · DPR
  core/          v3(벡터·쿼터니언) · rng · audio · save · input
  data/          tuning(모든 밸런싱 수치) · symbols(무늬 12종 벡터)
  game/          physics(XPBD 강체) · pile(더미와 집기) · session(진행·도구·점수)
  render/        camera(원근·역투영) · pile3d(면 정렬 렌더) · tiles · renderer · particles
  ui/            hud · screens · widgets · icons · rects
tools/
  physlab.mjs    더미가 제대로 서는지 (물리)
  simulate.mjs   봇이 실제로 푸는지 (게임)
```

밸런싱은 [src/data/tuning.js](src/data/tuning.js) 한 파일에 모여 있다.

## 디버그 훅

```js
TR.start(7)     // 레벨 7 로 시작
TR.visible()    // 지금 무늬가 보이는 타일 전부
TR.auto(3)      // 보이는 것 중 짝이 되는 세 벌을 자동으로 집는다
TR.rayAt(x, y)  // 화면 좌표에 무엇이 맞는지 (앞면인지까지)
TR.pile         // 더미와 물리 세계
```

## 현재 상태

브라우저에서 확인한 것: 실제 클릭으로 집기, 엎어진 면 클릭 거부, 도구 4종,
트레이 만석 패배와 이어하기, 레벨 이월 점수, 로컬 기록, 모바일 터치.

남은 것:
- **사람 손으로 하는 밸런싱** — 난이도는 봇으로만 확인했다
- 카메라 각도 조절 (지금은 고정)
- 큰 더미(120장)에서 화가 알고리즘이 드물게 어긋난다 — 클릭은 광선으로 하므로 조작에는 영향이 없다
